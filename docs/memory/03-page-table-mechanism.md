# EGOS 内核内存管理系统 - 页表与扩展页表机制

> **前置知识**：本文档假设读者已了解 x86-64 四级页表的基本架构，详见 [`02-memory-layout.md`](02-memory-layout.md#4-页表结构详解)

---

## 1. 设计动机

传统 x86-64 页表的每个条目仅包含硬件所需的映射信息和权限位。EGOS 需要额外的元数据来支持高级内存管理功能：

| 需求 | 传统方式的问题 | EGOS 的解决方案 |
|------|---------------|----------------|
| **内存操作策略** | 无法在页表中编码 COW、共享等语义 | 为每个页关联 operationsID |
| **引用计数** | 需要额外的数据结构跟踪共享页 | ExtraPageTableEntry 直接维护 |
| **延迟映射标记** | 无原生支持按需分页的标志位 | flags 字段提供 LAZY_MAP 等标志 |
| **快速查找** | O(log n) 遍历 VMS+VMR 获取页属性 | O(1) 直接从页表读取元数据 |

## 2. 扩展页表架构

### 2.1 核心设计理念

EGOS 的扩展页表采用**并行存储**的设计：每个标准页表旁边都维护一个同等结构的"额外页表"，用于存储扩展元数据。

```
┌────────────────────────────────────┐
│        ExtendedPageTable (8KB)     │
│                                    │
│  ┌──────────────┬────────────────┐ │
│  │  PagingTable │ ExtraPageTable │ │
│  │              │                │ │
│  │  Entry 0     │  Entry 0       │ │
│  │  Entry 1     │  Entry 1       │ │
│  │  ...         │  ...           │ │
│  │  Entry 511   │  Entry 511     │ │
│  └──────────────┴────────────────┘ │
└────────────────────────────────────┘
```

### 2.2 额外页表项的语义

每个 ExtraPageTableEntry 与对应的 PagingEntry 一一对应，存储以下信息：

| 字段 | 大小 | 作用 |
|------|------|------|
| **tableEntryNum** | 16 bit | 子条目数量（非叶子节点）或保留（叶子节点），0 表示未使用 |
| **operationsID** | 8 bit | 内存操作类型标识符，决定页的行为语义 |
| **flags** | 8 bit | 标志位（如 LAZY_MAP 延迟映射标记） |
| **reserved** | 32 bit | 保留用于未来扩展 |

### 2.3 四级层次结构

扩展页表在每一级都维护并行结构：

```
PML4 Level:
┌─────────────────────────────────────────────────────┐
│ ExtendedPageTable (PML4)                            │
│  PagingTable[512] ◄──► ExtraPageTable[512]          │
└─────────────────────────────────────────────────────┘
                    │
                    ▼ (selected entry)
PDPT Level:
┌─────────────────────────────────────────────────────┐
│ ExtendedPageTable (PDPT)                            │
│  PagingTable[512] ◄──► ExtraPageTable[512]          │
└─────────────────────────────────────────────────────┘
                    │
                    ▼ (selected entry)
Page Directory Level:
┌─────────────────────────────────────────────────────┐
│ ExtendedPageTable (Directory)                       │
│  PagingTable[512] ◄──► ExtraPageTable[512]          │
└─────────────────────────────────────────────────────┘
                    │
                    ▼ (selected entry)
Page Table Level:
┌─────────────────────────────────────────────────────┐
│ ExtendedPageTable (Page Table)                      │
│  PagingTable[512] ◄──► ExtraPageTable[512]          │
│                   │                                 │
│                   ▼ (physical frame address)        │
│            ┌──────────────┐                         │
│            │ Physical     │ ◄── ExtraEntry 包含此页的元数据
│            │ Frame (4KB)  │     - operationsID
│            └──────────────┘     - 引用计数等
└─────────────────────────────────────────────────────┘
```

## 3. 内存操作策略（Memory Operations）

### 3.1 核心概念

**MemoryOperations**是 EGOS 定义的接口，用于描述不同类型内存页的行为语义。每个 operationsID 对应一个 MemoryOperations 实例，定义了该类型页在以下场景的处理方式：

- **复制**：fork、clone 等场景下如何复制页表项
- **释放**：munmap、进程退出时如何清理资源
- **缺页处理**：访问未映射页时如何响应

### 3.2 内置操作类型

| ID | 名称 | "颜色"含义 | 典型用途 |
|----|------|------------|----------|
| 0 | SHARE | 共享页 | 多个进程共享的只读数据（如共享库代码段） |
| 1 | COPY | 复制页 | 需要立即复制数据的场景 |
| 2 | MIXED | 混合类型 | 部分共享、部分私有的复合场景 |
| 3 | COW | 写时复制页 | fork 后的文本/数据段，写入时才复制 |
| 4 | ANON_PRIVATE | 匿名私有页 | malloc 分配的堆内存，进程独占 |
| 5 | ANON_SHARED | 匿名共享页 | shmget/shmat创建的共享内存|
| 6 | FILE_PRIVATE | 文件私有映射 | mmap 的文件私有副本，修改不回写 |
| 7 | FILE_SHARED | 文件共享映射 | mmap 的文件共享映射，修改可见且回写 |

## 4. 页表操作接口

### 4.1 绘制映射（Draw）

**功能**：在页表中建立虚拟地址到物理地址的映射。

**关键参数：**
- 目标页表根节点
- 虚拟地址起始位置
- 物理地址起始位置
- 页数
- operationsID（决定"颜色"）
- 保护标志（读/写/执行权限）
- 额外标志（如 LAZY_MAP）

### 4.2 擦除映射（Erase）

**功能**：移除指定范围的映射。

**处理流程：**
1. 遍历页表找到对应条目
2. 根据 operationsID 调用相应的释放逻辑
3. 更新引用计数或释放物理页框
4. 清理页表项

### 4.3 查询操作（Peek）

**功能**：获取指定虚拟地址对应的内存操作类型，不触发缺页异常。

**用途：**用于检查某地址是否已映射以及其属性。

### 4.4 地址翻译（Translate）

**功能**：将虚拟地址转换为物理地址，纯查询操作。
