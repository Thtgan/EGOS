# EGOS 内核内存管理系统 - 内存布局与地址映射

## 1. 物理内存布局

### 1.1 启动阶段内存布局 (低地址区域)

```
地址范围                    用途
─────────────────────────────────────────────────────────────
0x00007C00 - 0x00007E00    MBR (主引导记录), 512 字节
0x00007E00 - 0x00010000    Bootloader, ~60KB
0x00010000 - 0x00040000    启动阶段内存分配区，~200KB
0x00080000                 内核栈底 (向下增长)
0x00100000 - ...           内核加载区域
```

### 1.2 E820 内存地图解析

系统通过 E820 DMA 接口获取物理内存布局信息，识别以下类型的内存区域：

- **RAM**：可用物理内存
- **Reserved**：保留区域
- **ACPI Data/Reclaimable**：ACPI 相关内存
- **I/O Memory**：设备映射内存

系统选择最大的连续 RAM 区域作为主要可访问内存范围。

## 2. 虚拟地址空间布局

### 2.1 48 位虚拟地址结构

```
┌─────────────┬────────────┬─────────────┬─────────────┬──────────────┐──────────────┐
│    Sign     │   PML4     │    PDPT     │   Directory │    Table     │    Offset    │
│  Extension  │    Index   │    Index    │     Index   │     Index    │              │
│   (16 bits) │  (9 bits)  │  (9 bits)   │  (9 bits)   │  (9 bits)    │  (12 bits)   │
└─────────────┴────────────┴─────────────┴─────────────┴──────────────┴──────────────┘
  Bits 48-63    Bits 39-47    Bits 30-38     Bits 21-29     Bits 12-20     Bits 0-11
```

### 2.2 虚拟地址空间划分

```
虚拟地址范围                              用途
─────────────────────────────────────────────────────────────────────────────
0x0000000000000000 - 0x000FFFFFFFFFFFFF  用户空间 (未使用)

0xFFFFF80000000000 - +128GB             VMS Space (虚拟内存空间映射区)
                                      用于映射物理内存帧到虚拟地址

0xFFFFFE0000000000 - +128GB             Colorful Space (彩色空间)
                                      用户页的虚拟地址区域，支持快速 P2V 转换

0xFFFFFF0000000000 - +128GB             Kernel Memory (内核内存区)
                                      内核页的虚拟地址区域，支持快速 P2V 转换

0xFFFFFFFFC0000000 - 0xFFFFFFFFE0000000  Kernel Text (内核代码区)
                                      内核代码和只读数据的直接映射区，512GB 空间
```

### 2.3 地址空间大小计算

| 区域 | 起始地址 | 大小 | 说明 |
|------|----------|------|------|
| VMS Space | 0xFFFFF80000000000 | 128GB | 物理内存映射 |
| Colorful Space | 0xFFFFFE0000000000 | 128GB | 用户虚拟页 |
| Kernel Memory | 0xFFFFFF0000000000 | 128GB | 内核虚拟页 |
| Kernel Text | 0xFFFFFFFFC0000000 | 512GB | 内核代码直接映射 |

## 3. 地址转换机制

对于 Kernel Memory  区域，系统采用**恒等映射偏移**的方式：

```
物理帧地址：    0x001234567890ABC0 (页对齐)
                    │
                    ▼
Kernel Memory 映射:
虚拟地址 = KERNEL_MEMORY_BEGIN + (物理地址 & OFFSET_MASK)
         = 0xFFFFFF0000000000 + 0x1234567890ABC0
         = 0xFFFFFF1234567890ABC0
```

这种设计使得虚拟地址和物理地址之间可以通过简单的加减法相互转换，无需查表。

## 4. 页表结构详解

### 4.1 四级页表层次

```
PML4 Table (Page Map Level 4)
│   512 个条目
▼
PDPT (Page Directory Pointer Table) 
│   512 个条目
▼
Page Directory
│   512 个条目
▼
Page Table
│   512 个条目
▼
Physical Page Frame (4KB)
```

### 4.2 各级页表覆盖范围

| 级别 | 条目数 | 每个条目覆盖 | 本级总覆盖 |
|------|--------|-------------|-----------|
| PML4 | 512 | 1GB × 512 × 512 × 512 = 256TB | 128PB (理论) |
| PDPT | 512 | 1GB × 512 × 512 = 1GB | 256TB |
| Page Directory | 512 | 2MB × 512 = 1GB | 512GB |
| Page Table | 512 | 4KB | 2MB |

### 4.3 页表项格式 (64 位)

```
┌─────────┬─────────┬────────────────────┬─────────┬────────┐
│   0     │   1     │      2-5           │   6-7   │  8-12  │

│         │         │  A, -, -, -        │         │        │
```

## 5. 内存区域类型与映射策略

### 5.1 内核代码区映射

内核代码区采用**大页映射**策略，直接映射到固定虚拟地址：

```
物理地址：0x0000000000001000 (内核加载地址)
                    │
                    ▼  通过页表映射
虚拟地址：0xFFFFFFFFC0001000 (KERNEL_KERNEL_TEXT_BEGIN)
```

### 5.2 物理内存映射策略

系统维护三个主要的物理到虚拟映射区域：

1. **VMS Space**：用于虚拟内存空间内部的数据结构映射
2. **Colorful Space**：用户进程的页帧映射，支持快速识别
3. **Kernel Memory**：内核分配的页帧映射，与用户空间隔离

### 5.3 映射关系示意图

```
┌─────────────────────────────────────────────────────────────┐
│                      物理内存                               │
│  ┌────────────────────────────────────────────────────────┐ │
│  │  RAM Regions (from E820)                               │ │
│  │  ┌──────────┬──────────┬──────────┬─────────────────┐  │ │
│  │  │ Frame 0  │ Frame 1  │  ...     │ Frame N         │  │ │
│  │  └──────────┴──────────┴──────────┴─────────────────┘  │ │
│  └────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
         │              │              │
         ▼              ▼              ▼
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│   VMS       │  │ Colorful    │  │  Kernel     │
│   Space     │  │  Space      │  │  Memory     │
│(直接映射)   │  │ (用户页)    │  │  (内核页)   │
└─────────────┘  └─────────────┘  └─────────────┘
```

## 6. 特殊地址区域说明

### 6.1 Colorful Space 命名由来

"Colorful Space"（彩色空间）这个名称来源于 EGOS 扩展页表的核心设计理念：**为每个物理页赋予类型标识，如同在画布上绘制不同颜色的区域**。

#### "着色"机制的实质

EGOS 通过扩展页表 (ExtendedPageTable) 为每个页表项关联一个 `memoryOperationsID`，这个 ID 标识了该页的内存操作类型：

| Operations ID | 类型名称 | "颜色"含义 |
|---------------|----------|------------|
| SHARE | 共享页 | 多个地址空间可读写共享 |
| COPY | 复制页 | 需要立即复制数据 |
| COW | 写时复制页 | 写入时触发复制 |
| ANON_PRIVATE | 匿名私有页 | 进程独占的匿名内存 |
| ANON_SHARED | 匿名共享页 | 可共享的匿名内存 |
| FILE_PRIVATE | 文件私有映射 | 从文件映射，私有副本 |
| FILE_SHARED | 文件共享映射 | 从文件映射，多进程共享 |
| MIXED | 混合类型 | 复合操作类型 |

#### 画布比喻

想象整个物理内存是一块巨大的**画布**，当进程访问内存时，扩展页表就像**画笔**一样：
- `extendedPageTableRoot_draw()` - 在画布上"绘制"一个有颜色的区域
- 每个页被赋予特定的 operationsID（颜色）
- 缺页异常处理时，根据页面的"颜色"采取不同的操作

#### Colorful Space 的作用

Colorful Space (0xFFFFFE0000000000 ~ +128GB) 是专门用于**着色**的区域。当内核通过 `mm_allocatePages()` 分配物理页框时：

```
1. 从 BuddyFrameAllocator 获取物理页框
2. 计算 Colorful Space 中的虚拟地址:
   vaddr = COLORFUL_SPACE_BEGIN + (frame_index × PAGE_SIZE)
3. 通过扩展页表建立映射，并赋予 operationsID（"着色"）
4. 返回 vaddr 给调用者
```

这种设计使得可以通过扩展页表可快速查询页面的"颜色"(operationsID)，来决定缺页处理策略
